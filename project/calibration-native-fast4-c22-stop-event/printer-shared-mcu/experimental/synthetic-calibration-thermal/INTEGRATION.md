# Explicit shared thermal profile integration

This is a separately selected hypothetical virtual environment. The component
`README.md` remains the original offline report, including its historical
statement that no central integration existed at that stage. This file records
the later integration, not a native temperature-control/calibration result.

## Selection and unchanged defaults

- Direct launcher: `--thermal-profile synthetic-calibration`.
- Existing native-event wrapper: `THERMAL_PROFILE=synthetic-calibration` and an
  explicit `GLOBAL_QUANTUM_US=1`. The wrapper already selects shared MCUs and the
  electromechanical-driver plant. A new run name is mandatory.
- Default `none` changes no generated bytes, including the previously tested
  synthetic Z plus autobaud composition. Firmware, Z models, MIPS, physical
  timers, clock sources/guards and default source profiles are untouched.
- The selected profile requires shared MCUs, electromechanical-driver, an
  explicit 1us global quantum, and the existing main24MHz external clock. It
  does not select Z or autobaud implicitly. Preserve their separate explicit
  flags for combined calibration.
- No thermal parameter overrides exist. `integration-reviewed-sources.json`
  pins the reviewed component, production thermal/nozzle-binding/observer and
  supported setup dependencies. A changed dependency requires explicit review,
  not silent substitution. Runtime manifests contain original/generated hashes.

## Exclusive fresh paused setup

`thermal_profile_selection.py` removes one exact reviewed stock bed/nozzle
loader, if present, from each setup command list before loading generated
models. It then installs the selected namespace-isolated fixture once, before
any execution. Missing stock loaders are also supported. Multiple loaders,
extra bindings/writers, unreviewed includes/inline platforms, GPIO/ADC/duty or
sensor writes, hot swaps/resets, early execution, clock overrides and live
monitor input are rejected. Supported setup inputs are deliberately narrow:
reviewed stock TMC/passive-TMC files, existing XY contact parameters and passive
motor tracing. Final user monitor commands are restricted to paused diagnostics;
they cannot reset/cool the plant or inject a success/fault state.

The actual resolved PB8/PA0 level initializes the bindings and subsequent real
GPIO edges drive thermal input0. No setup heater GPIO writes occur. PB9 stays
passively observed and thermally unbound. `NATIVE_NOZZLE_HEATER=1` conflicts with
the profile's exclusive binding ownership and is rejected before a run directory
is created. `PASSIVE_NOZZLE_TRACE=1` is redundant but compatible: only one
profile-owned observer/stream is created. Passive TMC/motor/contact/Z traces
remain separately selectable.

Nozzle60W/20J/K/0.2W/K and bed200W/600J/K/1.5W/K are exactly the tested component
parameters. Both original thermal classes remain unchanged, including curves,
10ms integration, environmental latches, sensor faults and warm-reset behavior.
The new bed observer is passive and does not call any plant integration method,
GPIO setter, ADC setter or CPU synchronization method.

## Telemetry contract

Before startup, `thermal-profile.json` is written and embedded verbatim in
`shared-profile.json["thermal_profile"]`. It records the complete parameter
choices, bindings, assumptions, source/generated hashes and telemetry limits.
Original firmware hashes remain in the shared profile. Native guard/temperature
state is not fabricated by a model observer.

Both profile-owned observers emit actual edges plus100ms snapshots, independently
bounded to100000 buffered rows and100000 live rows:

- `nozzle-thermal-live.csv`: unchanged existing nozzle schema, source-local
  `time_us`, actual PB8/PB9 levels/configuration/latches, physical temperature,
  published ADC, recovered curve, original fault/out-of-range/latch states,
  integrated duty and automatic update count.
- `bed-thermal-live.csv`: `time_us,virtual_time_ns,event,changed_pin,changed_level,pa0_level,pa0_config,pa0_latch,physical_temperature_c,published_adc_code,sensor_curve,sensor_fault,model_overtemperature,model_heater_latched_off,last_heater_duty,last_fan_duty,thermal_updates`.
  Bed time_us is a nonresetting observer-local1MHz counter, and virtual_time_ns
  is the source machine's elapsed epoch read directly without synchronization.
  The original bed model has no recovered table/out-of-range property; none is
  invented. Its B3950/100k/4700ohm divider remains an explicitly illustrative
  assumption.
- Final `nozzle-thermal.csv` / `bed-thermal.csv` and corresponding
  `.status.json`, plus `nozzle-thermal-live-status.json` /
  `bed-thermal-live-status.json`, report buffered/live counts, cap/drop/error
  counters and uncertain writes. `nozzle-heater-binding.json` /
  `bed-heater-binding.json` report original binding state. Final monitor output
  also exports original sensor/model fault/latch properties.

Streaming files use CreateNew and shared reads. Every row is flushed for live
inspection. At capacity the stream closes and subsequent drops remain counted;
an I/O failure records its error and uncertain outcome rather than changing
firmware/model state. Stream counters are exported at paused completion, not
continuously during the run. A controller must treat missing fresh periodic
rows as a stop condition and verify final counters before asserting capture
completeness. Native temperatures, accepted target and shutdown responses must
be observed independently through the original host/native route. Do not
subtract timestamps from unrelated clock domains.

- Seven generation/wrapper/negative tests pass. Four before/after cases preserve
  byte-identical generated output: electrical/default, electromechanical/default,
  electromechanical/autobaud, and the existing Z+autobaud combination with thermal
  disabled. Existing six shared-profile and six Z-profile tests also pass.

  Ambient nozzle/bed ADCs4023/3911, original clear model guards, no fan duty,

  verified. Zero live stream drops/errors.

  and update counts against an unobserved matched actual-GPIO plant, quarter-duty

  Explicit sensor faults appear only in this isolated negative test class, never

  fresh rerun passes36. Earlier evidence is preserved rather than overwritten.
- Protected original firmware, production thermal sources, default profiles,
